# 固定计划应答音频（2026-11-12）

目标：平台一次计划含多条动作时，机器人首次接受有效动作后播放一次“好的，这就去”。

## 本次文件
- ack_good_go.wav：真实豆包语音合成 2.0，小何默认标准音色；1.397 秒，24 kHz/单声道/PCM16。
- install_plan_ack.py：供用户在 Orin 执行的安装器；不连接平台，不启动/停止服务，不安装依赖，不提交 Git。
- robot-plan-ack.patch：与安装器一致的两个机器人源码文件差异，供审阅。
- verify_plan_ack.py：本机开发检查，不是真实机器人验收。

动作服务器接受目标，且没有受理期间挂起的取消请求后：
1. 命令桥通过 /deepleap/plan_ack（String JSON）发送 plan_id、cmd_id。
2. 语音节点读取开关和 WAV，向本地 SQLite 写入计划播报申请。
3. 同一 plan_id 已申请过时跳过，后续步骤、重复消息和语音节点重启不会重复排入播放队列。
4. 首次申请成功时放入已有播放队列，复用分块节奏、播放期间麦克风上传抑制和回声尾保护。
5. 音频读取/解码/记账/排队失败会记录错误，动作逻辑照常执行。
6. 播放线程异常会记录错误并继续等待后续音频。

## 本地资源与关闭
/home/astribot/.local/share/deepleap-robot/audio/
- plan_ack.wav：固定音频
- plan_ack.enabled：存在时启用；删除该标记文件即可关闭新播报，无需修改启动脚本
- plan_ack.sqlite3：首次接收到有效播报事件时创建，只存 plan_id、cmd_id、申请时间
数据库中是“尝试播报过”，不是“扬声器已成功发声”。SQLite 文件不包含语音 API 密钥。

## 边界
这里保证每个计划最多尝试排队播放一次，不保证一定发声。
申请写盘后若发生进程中断、队列满、stop/重连清队列或扬声器故障，该计划可能没播完，后续步骤不补播。
缺少 plan_id 的旧平台动作仍正常执行，只跳过播报。语音订阅者未就绪时记录日志，不阻塞动作。
开关关闭不撤销已经排队/已提交给扬声器的音频。
没有修改机械臂动作安全检查或任务完成判定。

## 安装行为
--check 仅核对源文件、补丁和 WAV，不写文件。
--apply 先验证文件哈希、分支/提交、服务 User=astribot、HOME，以及 ROS 实际加载的文件位置，再写入源码和资源。
发现代码不同、不同的已有 plan_ack.wav 或错误运行用户时停止，不覆盖。
同一安装包重复运行不会重复插入代码，也不会清空 SQLite 去重记录。
不创建备份。每个源码文件原子替换；安装中途失败时只回滚本次已写入且未被其他人改动的源码，保留并报告可能新增的音频资源。
修改不是已经运行的 Python 进程热更新；需要另行确认并重启机器人服务和平台。
