这是本次数据方案修改的清单，按开发顺序排列，不是重做整个项目。已有且符合要求的能力只验证，存在缺口的部分才开发；本表是未来完成标准，不是当前实现成绩。

| 顺序 | 开发项 | 完成标准 | 对应阶段／验收 |
| --- | --- | --- | --- |
| 1 | 业务数据入库 | 客户、账号、成员关系、机器人登记和动作规则由 PostgreSQL 管理；保留现有任务 ID 和历史关联 | D1；K02、K06、K10 |

## 目标与门禁

目标是账号、客户成员、机器人登记和客户政策由数据库驱动，业务变更不改部署文件、不重启。保留 FastAPI、PostgreSQL、单实例、首期一台机器人一个活动任务和 dlv/0；不实现多机、视觉／长期记忆，不引入缓存／消息队列／配置中心，不导入旧平台未结束任务。

完整字段、权威来源及生效规则以[数据边界清单](../../data-configuration-boundaries.md)为准。当前仍是启动静态身份／政策；账号登录和动态管理未实现。批准读取遗漏 approver_id、执行前未完整核对当前审批资格，迁表本身不会解决它。

| 阶段前置 | 需要确认 | 未解决时 |
| --- | --- | --- |
| D2 账号与管理 | 创建方式、登录交互、成员管理与跨客户权限边界 | 仅暂停依赖未定产品选择的步骤；内部会话方案由开发者设计，不用夹具决定政策 |
| D3 设备与政策 | 修改资格／生效流程、凭据轮换、在途 ID 映射维护 | 相关在线写入口不启用，不默认管理员全权 |
| D5 正式切换 | 初始化对象、秘密授权、维护窗口、备份与安全回滚 | 只测隔离环境，不读生产秘密或控制真机 |

上表用于记录相关阶段的未定事项，不是当前需要逐项回答的问卷。已确认的需求不重新讨论；只有实质影响功能、权限、兼容性或成本且无法从证据确定的选择，才在对应实现／启用前集中说明阻碍和建议。低风险内部技术细节按项目约定决定和验证，不让用户逐项选型，也不把未接受的建议写成已批准政策。

实际限额、外传与保留政策在相应能力启用前落实；未知在途证据不自动清理。停用清队列和机器人凭据失效拒收反馈的权威规则见[数据边界清单第 4.1 节](../../data-configuration-boundaries.md#41-读写责任与生效契约)。

## 依次实施

### D1 字段、接口与迁移设计

1. 设计客户、账号、成员、校验／撤销信息、机器人映射、客户政策版本、必要审计的关联；保持已有 customer_id/actor_id/binding_id。
2. 明确异步当前资格读取和客户政策／版本读取，列全 current_actor/self.policy.version 调用点，设计复合客户约束、唯一性及版本条件。
3. 说明管理变更与 DISPATCHING／实际写入门的协调及可能已下发窗口，网络不进入长事务；提交字段／接口方案评审。

涉及 domain、ports、postgres 和新编号迁移设计。完成条件：每个新字段对应清单，全部资格／版本调用点有归属，历史任务可读；具体表、内部接口与登录技术形成可审查的设计，不要求用户逐项选型。本轮仅更新文档，尚不实施。

### D2 账号登录与成员管理闭环

1. 按获准流程实现账号创建／登录／停用、成员授权和凭据失效；密码安全校验存储。
2. identity 的 resolve_web/current_actor 查数据库当前事实，补齐 await；旧 TrustedContext.roles 不能持续授权。
3. 管理入口经过可信身份、客户范围和操作权限检查，保存必要审计；客户端登录／必要管理交互实际调用后端，不是占位。
4. 停用时移除受影响、尚未开始执行的排队任务，记录取消并保留历史；与出队和实际写入门协调，已经开始或可能已下发的任务不当作未执行任务删除。

涉及 identity、账号／成员用例、HTTP／客户端和存储。完成条件：真实 HTTP＋隔离 PostgreSQL＋客户端验证新增／登录／停用／改角色无需改配置重启；停用清除受影响待执行队列，恢复启用不自动恢复已取消任务；跨客户拒绝，缺库不退回静态名单。

### D3 登记、政策与批准资格

1. 设备 ID 映射、启用、凭据引用、允许动作数据库化；维护不解除隔离，不放开第二台参与执行设备。
2. 客户政策不可变版本与生效引用同事务保存；受理／审批／出队／写入门按客户重查，不再依赖全局版本。
3. approvals() 保留 approver_id，核对当前审批资格、范围、版本、到期与撤销；旧凭据／长连接不沿用旧许可。
4. 撤权后停止后续新下发；停用清除受影响的待执行队列。机器人凭据失效后，已有连接的反馈也必须拒收，默认未完成原因显示“机器人凭据失效”；没有可靠终态的已发或可能已发指令保留结果未知和占用，不宣称动作停止、不改历史证据。仍有效的机器人凭据只在通过当前认证与归属检查后才能提供执行证据。

涉及 policy、identity、preflight、task_service、resources、dlv0、接入与存储。完成条件：在线变更无需重启；审批后撤角色则下一指令零发送；双客户政策隔离，历史／未知占用／dlv/0 保持。

### D4 部署与一次初始化分开

1. 正式配置仅部署和技术参数，users/robots/policy 经独立批准输入导入，不在启动覆盖在线更新。
2. 初始化检查冲突并幂等，保存校验／秘密引用；缺库拒绝装配／下发，不降级静态名单。
3. 首期容量按数据库参与执行范围检查，而非 len(configuration['robots']) 定义登记模型；核对参数类型／单位／上限和类默认值。

涉及 deployment、config、app、初始化入口和部署文档。完成条件：无永久全量业务名单，重启不覆盖 DB／隔离，无 fake 或内存生产回退；正式读取与文档一致。TTS／VoiceService 接线是单独语音工作，不因分类自动完成。

### D5 迁移、回归与切换

1. 隔离库验证导入预览、冲突、重复／失败事务及旧记录；保留历史 ID、批准和未知占用。
2. 回归 T05—T18、T23 和 K01—K10，真实 PostgreSQL／协议模拟／真机证据分开。
3. 获准窗口才备份／初始化／切换；先停新下发、核实在途，回滚不恢复过期授权、不重发物理动作。

完成条件：每项记录环境、结果及限制，未确认／未通过的相关能力不上线；文档或单元通过不能代替本阶段。

## 专项验收

| 编号 | 场景 | 必须观察到 |
| --- | --- | --- |
| K01 | 新增／停用用户、改角色，不重启 | 登录／写操作／下发按当前 DB；停用清除受影响、尚未开始执行的排队任务并保存取消历史，恢复启用不自动复活，其他客户队列不受影响；未改配置名单 |
| K02 | 双客户凭据、对象或政策混用 | 访问／关联拒绝，不泄露另一客户对象 |
| K03 | 批准后撤审批角色／停用成员 | 按 approver_id 核验资格，下一指令零发送 |
| K04 | 政策新版本、批准撤销／到期 | 旧批准不放行，等待／阻塞，已完成步骤不重做 |
| K05 | 停用设备／机器人凭据失效，旧 WS 存在 | 无新下发；停用清除受影响的待执行队列；失效凭据及已有连接的反馈拒收，默认未完成原因显示“机器人凭据失效”，不凭被拒载荷认领任务；原可靠结果不改写，无可靠终态的可能已发指令保留未知和占用，不宣称停机 |
| K06 | 登记变更、重启 | 不覆盖 DB／隔离／历史，首期容量不放开 |
| K07 | 身份／政策／存储读取失败 | unavailable／阻塞，零新下发，无静态／缓存后备 |
| K08 | 初始化重复／冲突／事务失败 | 幂等或拒绝，不覆盖在线更新，无半份关系 |
| K09 | 在线停用／撤权与出队／下发并发 | 清队列、检查与写入门按统一锁约定协调；尚未开始的任务取消且零发送，已经开始或可能已发的任务保留证据／未知和占用、不重发；事务失败不留下半份变更 |
| K10 | 源码读取／DDL与文档核对 | 字段有来源／生效规则，秘密不进日志、响应、模型或补丁 |
