# 本机测试平台日常启动（第二步）

状态：用户已确认本轮范围；2026-11-09 已完成实现和真实启动验收。设计对照当前源码、第一步配置与 V5 启动/隔离约束检查。此记录只覆盖本轮启动脚本，不继承历史测试或真机验收结论。

## 目标与职责

在 Windows Git Bash 中运行根目录 `start-dev.sh`，读取 `test-db/local-runtime.json`，准备独立测试 PostgreSQL，启动当前项目真实应用。Ctrl+C 正常关闭本次平台，数据库继续运行。用户可从终端输出和配置中核对启动顺序。

薄 shell 入口只定位项目和配置指定的 Python；Python 辅助程序负责参数检查、数据库进程准备、环境装配及 Uvicorn 进程生命周期。现有 `robot_agent.app:create_app` 继续负责业务装配、迁移、机器人登记与恢复；不复制业务逻辑。

## 已确认步骤

1. 在特性分支实施，保留第一步 .gitignore 及本机文件。
2. 先写显式运行的真实环境验收入口，确认启动器缺失时失败，再实现启动器。
3. 读取配置与独立凭据；核对项目目录、数据库目录、loopback 地址、端口、应用配置引用。拒绝正式端口/库名/目录及不属于项目的写入路径。
4. 先占用本次 HTTP socket，避免误用已有平台。对指定数据目录查询 pg_ctl 状态；未运行时确认数据库端口可用，再启动指定集群。已有实例必须通过连接与真实 data_directory 核对。仅用独立管理员凭据做只读预检；平台只使用测试应用账号。
5. 不运行 initdb，不创建或清空数据库，不重新复制正式配置，不输出密码/令牌。数据库准备失败时不启动应用。
6. 通过真实应用工厂启动 Uvicorn；Ctrl+C 走应用正常关闭过程，不调用系统范围的 kill，不停止 PostgreSQL。数据库后台进程必须与平台控制台退出分离。
7. 更新启动说明，给出可复制命令及未验证范围。

## 验收与范围

- 首先真实运行入口得到缺失失败（红）；实现后跑真实 HTTP/API/PostgreSQL（绿），不使用业务替身。
- 测试库未启动：仅停止本项目 55440 实例后运行 .sh，库和平台依次成功启动。
- 测试库已运行：复用同一实例，身份/机器人登记/空历史保持不变。
- 在独立隐藏 Windows 控制台发送真实 Ctrl+C：等待 Uvicorn 正常关闭，18764 释放，55440 继续连接成功。不能用直接调用 server.should_exit 或强杀进程代替此项证据。
- 已有平台占用 18764：第二次启动应明确失败，不结束第一个平台。
- 错误数据库密码：使用项目内临时配置/凭据进行启动器认证检查，应失败且不启动平台；不修改真实业务结果或正式凭据。
- 配置错指正式端口/项目外数据目录：启动前拒绝，不连接正式实例。
- 记录源码版本、实际输入与输出、前后表数量、退出状态；完成后测试库运行，测试平台关闭。

不验收模型、ASR/PCM、机器人协议收发或真机动作；不更改这些开关；不部署正式平台。不开启未获准的热重载或数据库自动停止策略。
