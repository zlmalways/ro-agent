# 机器人免审批执行

在舰队页选择机器人后，具有当前客户审批权限的用户可以修改“免审批执行”。每台机器人独立保存，默认关闭；刷新页面或重启平台不会重置开关。

开启时，新计划通过原有检查后直接等待执行；关闭时，按原有审批规则处理。开关只免去人工批准，不改变操作权限、能力和地点校验、机器人就绪检查、执行总开关及逐步等待回执的规则。

## 切换时如何处理已有计划

以计划记录保存时的开关值为准，该值与计划一起保存，之后不能修改：

- 开启时生成的计划，中途关闭开关仍可执行后续步骤，包括停止当前动作后的继续。
- 等待批准的旧计划，开启开关后仍需批准。
- 切换时还在生成中的计划，保存时读取最新开关值。开关保存和计划保存共用现有短事务锁，按保存先后确定结果。
- 同一会话中后续生成的新计划重新读取开关，不继承上一轮的值。

## 数据与记录

- `0017_robot_approval_bypass.sql`：在 `ra_robot_bindings` 保存开关、独立修改编号、修改人和时间。启动登记机器人时不覆盖这些设置。
- `0018_plan_approval_bypass.sql`：在 `ra_plans` 保存本计划采用的开关值及修改编号。历史计划默认不免审批。
- `ra_decisions` 的授权记录保留原政策结果以及本计划的免审批设置，不伪造人工批准记录。
- 修改开关写入 `robot_approval_bypass_changed` 日志。两个页面使用同一旧编号保存时，后保存者收到冲突提示，需要重新读取。

两个迁移由现有启动流程执行；本次代码修改未执行迁移、未重启服务、未更新发布目录。

## 待运行的验收

以下场景尚未运行。应从实际页面提交任务，使用真实数据库、模型和机器人，最后核对页面、计划及授权记录和机器人执行记录。

| 场景 | 预期 |
| --- | --- |
| 开关关闭，提交原本需要审批的任务 | 等待批准；批准前不下发动作 |
| 开关开启，提交新任务 | 校验通过后执行，不出现人工批准等待；没有伪造批准记录 |
| 免审批计划执行中关闭开关 | 当前计划后续步骤正常推进；下一份新计划恢复原审批要求 |
| 免审批计划停止当前动作后关闭开关，再继续 | 按原暂停规则跳过已停止动作并继续，不因关闭开关要求补审批 |
| 旧计划等待批准时开启开关 | 旧计划继续等待批准 |
| A 开启、B 关闭，再刷新页面 | 各自设置保持，不串机器人；重启后设置仍保留 |
| 无审批权限的账号或其他客户访问 | 不允许修改；不能借机器人编号修改其他客户的设置 |
| 两个页面同时修改同一机器人 | 旧设置不能覆盖新设置；冲突后刷新可读取最新状态 |
| 免审批开启，但机器人未就绪、计划不合法或权限拒绝 | 原有检查继续阻止下发 |

已完成的验证仅包括 Python/JavaScript 语法、差异检查，以及使用实际审批检查代码的开发检查。未用模拟结果代替上述验收。
