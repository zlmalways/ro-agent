# 语音唤醒判定与续话计时

平台收到模拟机器人的 PCM 后，先检测有效人声并记录这一句的续话资格，再完成“切成 WAV → 官方 ASR 转文字 → 匹配唤醒词或使用已记录的续话资格”，返回可核对的结果。`evaluate_wake=true, submit_tasks=false` 时，`command` 只表示这句话符合唤醒规则，不创建任务。两项同时为 true 时，PCM 的有效指令进入现有任务链路；没有唤醒或只喊名字不建任务。两种组合都不发声。

实现分支：`feat/robot-agent-v1`。历史唤醒验收使用独立真实平台和独立测试数据；新接入任务的完整验收尚未执行。本文件不代表已切换用户正在使用的平台。

## 配置

平台配置增加以下内容：

```json
{
  "voice_pcm": {
    "enabled": true,
    "submit_tasks": false,
    "evaluate_wake": true
  },
  "voice_wake": {
    "wake_word": "小千小千",
    "aliases": ["小千", "小钱小钱", "小芊小芊"],
    "followup_seconds": 10
  }
}
```

- `evaluate_wake=true, submit_tasks=true`：PCM 先转写并判断唤醒，仅 `command` 提交现有任务入口。保留两项单独开启及只切句的旧组合，本轮不清理。完整 WAV 的 HTTP/WS 入口仍只验唤醒，不随该组合创建任务。
- 两种处理模式都要求 `voice_pcm.enabled=true`；未打开处理模式时仍可仅切句。
- 唤醒词、兼容写法、续话时长由 `voice_wake` 配置控制；上面的值也是本步默认值。
- ASR 复用已有适配器。提供方与模型仍从配置环境读取：`VOICE_ASR_PROVIDER`、`VOICE_ASR_OPENAI_MODEL`；官方密钥来自 `VOICE_ASR_OPENAI_API_KEY` 的既有凭据装配，不写入仓库。本轮实际使用 `openai` / `gpt-transcribe`。
- 规划模型仍按原有 `DEEPLEAP_LLM_PROVIDER`、`RELAY_MODEL` 配置装配；仅验唤醒时不调用，启用唤醒后建任务时沿用正常规划。没有在唤醒业务代码里写死 ASR 或规划模型名。
- PCM 最大句长当前默认为 15 秒；切句参数仍按原配置读取。本步不改变超长句的断开连接处理规则，也不把超长句交给唤醒判定。

## 输入、处理和输出

### 设备入口

机器人使用已登记的语音身份连接 `/api/voice/robot/ws`。持续发送的每包格式仍为：

```json
{"type": "audio", "pcm_b64": "<原始 PCM 字节的 Base64>"}
```

PCM 格式为 16 kHz、单声道、16 位小端；数据包本身不是 WAV。平台按真实切句服务检测语音与静音，将结束原因为 `silence` 的完整句转换为 WAV，再转写一次。

正常一轮返回：

1. `state: thinking`：当前音频句开始处理，模拟器据此停止本轮上传。
2. `pcm_segment`：音频段 ID、实际 WAV、时长、结束原因和收包信息。
3. `pcm_wake`：实际转写文本及唤醒判定。
4. `pcm_task`：仅启用唤醒后建任务且判定为有效指令时返回，关联本句音频段及任务。
5. `state: idle`：本轮输入处理结束，不代表任务执行完成。

既有整段 WAV 的 WS 入口和 HTTP `/api/voice/robot/chat/stream` 也复用转写及唤醒判定服务；它们不经过 PCM 切句，没有实时人声活动证据，因此没有 `pcm_segment` 回包。整段 WAV 在进入转写前只记录当前资格，不凭上传、客户端 `woke` 标记或普通转写完成刷新窗口；其具体兼容规则见下文。`pcm_wake` 这个回包名在这些入口也沿用；HTTP 使用请求 ID，未提供时生成 ID，WS WAV 为该轮生成 ID。

### 服务职责

- `PcmSegmentService`：检测真实人声和静音，将 PCM 切成 WAV，不判断唤醒词。`feed_pcm()` 保留只返回 WAV 的旧接口；`feed_pcm_events()` 返回按处理顺序排列的 `SpeechActivity` 和 `AudioSegment`。
- `SpeechActivity`：记录服务端观察到的句 ID、候选人声开始时间和本次有效人声确认时间。达到既有最少 288 毫秒人声门槛后才产生，静音或只收到网络数据包不会产生。
- `VoiceWakeService.observe_speech()`：在平台事件循环中接收人声事实，确定本句资格，并在符合资格的后续人声到来时刷新窗口。切句 worker 不直接写唤醒状态。
- `FollowupAdmission`：绑定可信机器人与句 ID 的不可变资格记录，接受或拒绝都固定，不因后面 ASR 变慢或另一次唤醒而改判。
- `InputService.transcribe_audio()`：复用真实 ASR，保存输入与转写，不创建任务。
- `VoiceWakeService.evaluate(..., admission=...)`：匹配转写中的显式唤醒词，或按事先记录的资格返回指令文字；普通 ASR 完成本身不续期。
- `VoiceWakeEvaluation`：连接转写和判定，核对资格属于当前机器人和当前句，返回关联 ID 与耗时；不调用 `TaskService.submit()` 或 TTS。

机器人身份来自认证后的绑定，不采信音频消息自行声明的身份。唤醒状态按 `(customer_id, binding_id)` 隔离，资格还绑定本句 `segment_id`。应用人声活动、ASR 开始前及结束后都检查对应 WS 是否已被替换；失效连接不能继续更新唤醒状态。同一个数据包里的活动先按顺序确定资格，再开始等待任何一段 ASR，避免后来的识别结果倒过来改变此前音频的资格。

### 判定回包

`pcm_wake` 的字段如下；`command` 表示被接受的指令文字。仅验唤醒时到此结束；启用 PCM 唤醒后建任务时，还会返回同一 `segment_id` 的 `pcm_task`。该回执只是任务受理，成功以任务落表及机器人指令回执为准。

| 字段 | 含义 |
| --- | --- |
| `segment_id` | 对应 PCM 音频段；整段 WAV 入口使用该轮请求 ID |
| `input_id` | 对应 `ra_inputs` 中的输入记录 |
| `transcript` | ASR 实际返回、去掉首尾空白后的文本 |
| `provider_ref` | ASR 提供方和请求引用 |
| `asr_reused` | 是否复用了同一请求 ID 已保存的转写 |
| `action` | `ignore`、`wake_only` 或 `command` |
| `command` | 去掉唤醒词后留下的文字；续话时为该句文字；未接受时为空 |
| `matched_alias` | 实际匹配的唤醒词/兼容写法；未匹配时为 `null` |
| `reason` | 判定原因，如 `wake_word_only`、`wake_word_with_command`、`awake_followup`、`awake_expired`、`not_awake` |
| `awake` | 本次判定完成时是否处于续话窗口 |
| `remaining_ms` | 本次判定完成时剩余窗口毫秒数 |
| `timings_ms` | 本次 `asr`、`wake`、`total` 耗时 |
| `evaluated_at` | 文字判定完成时的服务端单调时钟秒数 |
| `deadline_at` | 当前续话窗口截止的服务端单调时钟秒数；从未唤醒时为 `null` |
| `followup` | 当前句在 ASR 前记录的资格及人声时间，字段见下文 |

ASR 失败、空转写、输入冲突等返回错误，不伪造成功判定，也不创建任务。普通非唤醒讲话则返回正常的 `ignore`。

`followup` 包括 `segment_id`、`accepted`、`reason`、`source`、`captured_at`、`first_speech_at`、`last_speech_at`。`source=pcm_vad` 表示真实 PCM 人声活动；`source=audio_upload` 表示整段 WAV 的接收资格快照，后者没有实时人声时间。`captured_at` 对 PCM 是达到有效人声门槛并首次确定资格的时刻；`first_speech_at` 只是候选人声起点证据，不用于把资格回溯到确认之前。

这些时间使用平台单调时钟，适合对照同一服务进程的先后与间隔，不能直接当成 UTC 时间。`awake/remaining_ms` 描述判定结束时当前窗口状态，`followup.accepted` 描述这句先前是否已被接住：两者可能分别是 `false` 和 `true`，此时仍可以返回 `command`，因为已接住的一句不会被 ASR 等待撤销。

## 10 秒续话规则（计时修复后）

例如机器人听到“小千小千”，ASR 识别出这个显式唤醒词后打开 10 秒窗口。用户在第 9 秒开始说“请去前台”，平台在窗口内确认有效人声，就接住这一句并从确认时刻重新计 10 秒；接下来每次检测到这一句的有效人声，都刷新截止时间。即使文字在原来第 10 秒之后才返回，也不会再把这句判为续话过期。

具体规则：

- 未唤醒时说“请去前台”：不能靠普通人声自行开窗，返回 `ignore`。
- “小千小千”：识别到显式唤醒词后开窗，返回 `wake_only`，不发提示音或语音回复。
- “小千小千，请去前台”：返回 `command`，提取“请去前台”。
- PCM 窗口内首次确认有效人声：固定本句的接受资格，按该次观察时间刷新为其后 10 秒。候选音开始但尚未达到有效门槛，不提前续期。
- 已接住的这一句持续检测到有效人声：不断更新 `last_speech_at` 和截止时间。网络分包、静音、`stats` 和普通 ASR 返回都不刷新。
- 首次确认有效人声时窗口已过期：固定本句的拒绝资格；后面继续说话不能自行重新唤醒。转写中实际出现显式唤醒词，仍可重新开窗。
- 已接住的一句跨越原窗口后才转写完成：仍返回 `command`。不会用 ASR 完成时间重新检查或重置它的续话资格。
- 单段 PCM 音频上限仍是 15 秒，按累计音频帧计数，与 10 秒续话时钟独立，不随每次人声刷新。超长句仍按原路径返回 `PCM_TOO_LONG` 并关闭该语音连接，不交给 ASR。
- 显式唤醒词匹配继续忽略标点、空格及常见全角差异，在整句查找兼容词，保留最后一次匹配后的文字；同一结束位置优先较长词。

整段 WAV 没有实时人声活动，进入 ASR 前只记录当时的资格；普通转写依此放行或忽略，不做 PCM 式人声续期。上传动作、客户端 `woke` 标记和普通 ASR 返回均不更新截止时间，识别到显式唤醒词仍能开窗。这个入口不能证明录音时实际何时开口。

状态保存在当前平台进程内。WS 断线会清除该连接未完成句的临时资格，但不会主动清除机器人尚未过期的窗口；重连可继续使用剩余时间。平台进程重启会丢失窗口。本步没有跨进程共享唤醒状态。

## 中间结果与耗时

转写仍保存到现有 `ra_inputs`：`input_id`、请求键、文本 `normalized_text`、提供方引用 `provider_ref`。只验唤醒或未建任务时状态为 `TRANSCRIBED`、`result_task_id` 为空；有效指令进入任务后为 `COMPLETE`，并关联真实任务编号。两者都不需要增加表或迁移。原来已经关联任务的 `COMPLETE` 输入重试不会被这次抽取的转写方法降级；唤醒验收拒绝拿已有任务输入重新判定。

唤醒判定当前可通过 WS/HTTP 回包和保存这些回包的验收报告查询；代码也有 INFO 日志调用，但是否实际写入服务日志取决于日志配置。**没有新增判定结果数据库表，耗时与资格时间尚未单独落表**。音频 WAV 保存在验收目录，不表示已实现业务音频存储。连接 `segment_id → input_id` 可以对照音频文件、判定报告与转写记录。

当前耗时口径：

- `timings_ms.asr`：真实 ASR 调用整体耗时，包含连接、上传及等待；复用已保存转写时为 0。
- `timings_ms.wake`：文字匹配与窗口判定耗时。
- `timings_ms.total`：本次转写与唤醒流程的总耗时，含输入落表等开销；不含前面的 PCM 收音和切句等待。
- 模拟器 `elapsed_s`：从本轮上传计时开始到收到结束状态的时间，包含音频上传/静音等待，不能当作纯 ASR 延迟。
- `pcm_segment.duration_ms`：音频自身长度，不是平台计算耗时。

以后统计整条业务链路，应沿用音频段/输入/任务 ID 关联，补齐首包、切句完成、ASR 开始/结束、唤醒完成、任务受理、规划开始/结束、指令下发/回执的时间点。用统一 UTC 时间还原先后，用单调时钟计算阶段耗时；同时区分“首包到结果”和“说完到结果”。本步只提供上面的实测计时，没有声称已经完成规划及执行全链路计时。

### HTTP 重试边界

HTTP 用同一个请求 ID 和相同音频重试时，ASR 文本会复用，但会重新取得接收资格并执行文字判定。普通续话返回不再刷新窗口；若文字包含显式唤醒词，仍可能再次开窗，或因重试时窗口状态不同得到不同结果。当前没有缓存首次唤醒判定；本步按每段只评估一次验收。此边界已记录，未修改重复请求策略。

## 模拟器验收方式

`tests/manual/mock_robot_ws.py send-pcm` 从合法 WAV 提取 PCM，默认加前后静音，每 20 毫秒发一包真实音频数据。它不发送预设转写或唤醒结果。下例中的地址、身份和路径需替换为独立测试平台的实际值，令牌由已有 `RO_AGENT_ROBOT_TOKEN` 环境变量提供：

```powershell
python tests/manual/mock_robot_ws.py --url "ws://127.0.0.1:<独立端口>/api/voice/robot/ws" send-pcm "<输入.wav>" --voice-id "<测试语音身份>" --expect-wake --timeout 120 --output-dir "<全新结果目录>"
```

`--expect-wake` 单独使用时仍拒绝任务；与 `--expect-task` 一起使用时，模拟器要求每个 `command` 段恰好关联一个任务，其他段没有任务。每个 `pcm_wake` 必须关联已经收到的 `pcm_segment`，每段恰有一个判定；语音连接拒绝指令和音频/TTS 回包，并将真实结果写入 `pcm-upload-report.json` 的 `wake_results`，实际切出的 WAV 单独保存。这些回包检查不能替代数据库核对：拒绝及只唤醒场景应无任务、计划和指令；有效指令场景应核对输入、任务、计划、指令及最终反馈的关联和数量。

这个单次命令结束后会断开自己的连接，不清空服务器的 10 秒窗口；连续场景可以在同一已认证 WS 上逐轮上传和核对。本步真实验收使用真实启动装配、真实切句、真实官方 ASR 和真实输入存储，没有 mock 被验收的业务逻辑。
